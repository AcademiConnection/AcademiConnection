# Lab Profile — 教师学术网络调研

这个技能用于把“查一个实验室”落实为可复核的教师网络报告集合。重点是识别真正属于该团队的核心与重要教师，研究其学术关系与合作网络，而不是机械罗列所有网页成员或为凑数量把学生、博士后、论文作者当成教师。

## 开始前

先确认工作区和现有约定。若项目已有报告目录、格式模板或用户提供了交付要求，优先沿用其中的输出路径、文件命名和报告格式；它们是当前项目的交付契约。没有既有约定时，再根据项目结构建立清晰、稳定的目录与命名。

为这次调研创建任务清单，并按团队或用户给出的顺序推进。调研、报告撰写、事实交叉核验、README 和最终格式检查应是可追踪的阶段。对包含多个团队的请求，不要把所有研究混成一轮搜索：完成一个团队的名单判断和资料收集后，再进入下一个团队；独立、耗时的资料核查可以并行，但最终结论要逐项回收和统一。

## 选人原则

先从官网、学院师资页、实验室成员页和个人主页确认团队边界，再决定建档对象。

优先收录团队负责人、共同 PI、实际承担稳定研究方向的教授/副教授/研究员、以及在该团队中具有明确领导职责或长期公开贡献的重要教师。用户点名的人通常应优先覆盖。若团队教师较少，可以继续扩展到确有团队归属的其他现任重要教师，而不是用学生、博士后、行政合作者或已离职成员填充数量。

要特别处理这些常见边界：同一中心或学院的教师不必然属于同一个课题组；共同论文不必然是师生关系；实验室中的多 PI 可能各有独立团队；一名教师可能同时出现于两个组织平台，但只需建立一份主报告，并在其他目录或 README 中交叉引用，避免重复和冲突。对已离职、兼职、双聘或历史成员，注明时间和身份，不把他们当作当前核心教师。

当名单口径存在不确定时，用公开可确认的事实解释取舍即可，不需要为了形式完整而强行下结论。

## 调研方法

以一手来源为主，包括机构官网、学院/实验室主页、个人主页、正式论文页面、会议或奖项官网、官方新闻和项目公告。使用 `web_search` 定位来源，需要完整上下文时再用 `web_fetch`。学术数据库和可信媒体适合补充论文、引用和产业新闻，但不应覆盖官方信息。

对每位入选教师，围绕以下信息建立证据链：当前职务与团队角色、教育和职业履历、明确可证的导师或学术传承、学生及其去向、长期合作者、代表成果、重要奖项与学术服务、产业合作与成果转化。研究学生时优先寻找实验室名单、个人主页、学位答辩页、院系新闻或正式毕业信息。只有论文署名时，只能称为论文合作者或团队成员，不能推定为学生或共同指导对象。

对行业合作也保持相同边界：区分个人项目、课题组合作、实验室平台合作和学校层面合作；不要因为某公司与机构合作就自动归给某位教师。涉及创业、公司职务、融资、商业落地规模时，优先采用公司或机构公开材料；无法确认时使用“公开资料未披露”或改为更审慎的团队层面描述。

遇到同名、时间线冲突或不同来源的职务不一致时，先消歧再写入。优先使用更新时间更近、主体更权威的来源；若无法消除冲突，保留来源差异而不擅自选择一方。

## 分阶段工作流

先完成团队层面的定位和选人。记录实验室全称、所属机构、官网、研究主题、当前教师名单与拟建档名单，并解释必要的边界判断。

然后按顺序研究每位教师。对于多人批次，可以用不超过六个子任务并行撰写独立报告，但每个子任务必须拿到具体对象、已知事实、主页链接、输出路径、格式约定和关系边界。子任务应写入指定文件；主线程负责统一判断、跨报告一致性与最终修订。

所有教师报告完成后，单独开展交叉验证，而不是把它当作写作过程中的可选步骤。交叉验证至少检查：职位、教育年份和导师；学生与论文作者的关系；奖项名称、年份与排序；企业/创业归属；同一人在多份报告中的时间、职务与关系是否一致；中文姓名和术语是否有错字或乱码。验证子任务只报告问题和来源，主线程再逐项修正，以免不同代理做出互相矛盾的修改。

报告稳定后，为每个团队目录撰写 README。README 应概述团队定位、已覆盖教师、研究方向和关系圈层、具有公开依据的产业转化亮点，并说明必要的团队边界。它是索引，不应把未建档人员扩写成确定教师，也不需要另设验证说明章节。

最后运行格式与空白检查，并结合 `git diff --check` 或同等检查确认交付物干净。若项目已有格式脚本，直接使用；否则检查头部、章节数量、文件命名、乱码、禁止章节和 Markdown 空白。发现问题后修复并再次检查。

## 报告写作

默认每位教师一份独立中文 Markdown 报告。若用户或项目现有模板规定了标题、头部、章节结构或文件名，严格遵循该规范。没有明确模板时，报告通常应覆盖基本信息、教育履历、学生培养、学术合作网络、业界合作、奖项与学术服务、Connection 圈层总结。

学生培养和业界合作应有足够信息密度，但证据不足时宁可写清公开资料边界，也不要补造细节。把“直接指导”“联合指导”“团队培养”“论文合作”“同事关系”明确区分。教师报告中不添加“验证”“核实说明”之类附加章节；核验工作应体现在事实修订和最终交付质量中。

## 输出与收尾

完成时说明已覆盖的团队和教师、报告目录、是否存在需要保守表述的关键边界，以及事实核验和格式检查的结果。不要把内部搜索过程、无关中间文件或冗长操作日志写进最终报告。

保持研究方法充分但不过度流程化。不同机构的公开资料质量、团队规模和用户目标会不同；据此调整搜索深度、教师覆盖范围与并行程度。避免把偶发示例或偏好固化为僵硬规则，也不要生成与任务无关的说明性文本。
